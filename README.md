## Ciclos y branching

El protocolo A–J declara la pregunta y el estimando, rivales abiertos, prueba discriminante, instrumentación, ejecución, auditoría adversarial, confirmación cuando exista, doble actualización, dictamen y decisión. La exploración no se convierte en confirmación por usar semillas nuevas del mismo generador.

En una campaña solicitada como branching dinámico, registrar qué resultado motivó la siguiente pregunta, sus alternativas, falsador y versión de protocolo/código. El observatorio distingue un ciclo sustantivo de sus condiciones y réplicas, y propone eventos de decisión y bloqueos de fuente para evitar presentar una batería preescrita como rediseño continuo. Estas propuestas siguen identificadas como tales; no se incorporan silenciosamente al núcleo.

**Un cupo es un límite, no un objetivo.** R5 permite STOP, REPAIR o PIVOT antes de agotarlo cuando los ensayos disponibles no aportarían una clase nueva de evidencia. Conservar hallazgos negativos, reparaciones, ramas cerradas y el estado real del holdout.

## Qué se puede concluir

AB 3.2.1 es una revisión metodológica provisional. No tiene superioridad empírica general acreditada frente a una investigación convencional competente. Un resultado LARP o Goodhart no valida automáticamente AB; una prueba de infraestructura, un hash o un commit tampoco valida una afirmación científica.

El [benchmark AB-E2E-01](benchmarks/AB_E2E_01/README.md) contiene un protocolo e instrumentación para comparar procedimientos. Su estado declarado es **preparado, sin ejecuciones científicas independientes de agentes**; las comprobaciones sintéticas de software se conservan por separado.

- Enlazar informes extensos de Drive con repo, commit exacto, ciclos, fuentes y límites. Las discrepancias se resuelven mediante errata visible.
- Registrar las mejoras propuestas en el observatorio con fuente, alcance, contraevidencia y falsador; una incorporación documental no autoriza una actualización normativa silenciosa.
