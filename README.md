# Metodología AB

Repositorio privado de la metodología de investigación abductivo-bayesiana **AB**, sus priors metodológicos y observaciones acumulativas. GitHub conserva el registro científico versionado; Drive es el archivo documental complementario. Los resultados sustantivos de cada proyecto conservan sus propios repositorios y ledgers.

## Protocolo portable de interacción con ChatGPT (lectura obligatoria)

**[AB 3.2.1-O6 — campañas, informes, gráfica CT2 y autorización de ciclos](docs/AB_3_2_1_O6_CAMPANAS_INFORMES_CT2_Y_CICLOS.md)**. Las instancias que continúen una investigación AB deben seguir este contrato: ciclo A–J, CT2 1–100 por línea, escala DRIFT D0–D5, registro permanente de hallazgos 1/3, gráfica CT2 de escala completa y ampliada al cierre, y **solicitud final de 20–45 ciclos AB**, sin pedir otra vez bloques ya autorizados. Véase también **[AGENTS.md](AGENTS.md)** para el orden de lectura y recuperación en sesiones nuevas. Son reglas de presentación y gobernanza, no un método demostrado para alcanzar 2/3.


## Mapa universal, modo proyectos y AB autocorrectivo (O7, piloto)

**[AB 3.2.1-O7 — Grafo universal, modos de proyecto y autocrítica recursiva](docs/AB_3_2_1_O7_GRAFO_UNIVERSAL_MODOS_Y_AUTOCRITICA.md)**: toda nueva iniciativa AB debe empezar, bajo el piloto, con un grafo JSON versionado y una vista interactiva; AB-R investiga, AB-P desarrolla productos, AB-H combina sin mezclar evidencias y AB-META evalúa la propia metodología. Cada ejecución tiene recibo ligero y complaints opcionales. **AB puede modificarse, revertirse o reemplazarse**; O7 no acredita mayor eficacia, ni modifica retrospectivamente las campañas existentes. El prototipo externo aún requiere validación visual, integración con repositorios y evaluación frente a alternativas competentes.

## Ciclos y branching

El protocolo A–J declara la pregunta y el estimando, rivales abiertos, prueba discriminante, instrumentación, ejecución, auditoría adversarial, confirmación cuando exista, doble actualización, dictamen y decisión. La exploración no se convierte en confirmación por usar semillas nuevas del mismo generador.

En una campaña solicitada como branching dinámico, registrar qué resultado motivó la siguiente pregunta, sus alternativas, falsador y versión de protocolo/código. El observatorio distingue un ciclo sustantivo de sus condiciones y réplicas, y propone eventos de decisión y bloqueos de fuente para evitar presentar una batería preescrita como rediseño continuo. Estas propuestas siguen identificadas como tales; no se incorporan silenciosamente al núcleo.

**Un cupo es un límite, no un objetivo.** R5 permite STOP, REPAIR o PIVOT antes de agotarlo cuando los ensayos disponibles no aportarían una clase nueva de evidencia. Conservar hallazgos negativos, reparaciones, ramas cerradas y el estado real del holdout.

## Qué se puede concluir

AB 3.2.1 es una revisión metodológica provisional. No tiene superioridad empírica general acreditada frente a una investigación convencional competente. Un resultado LARP o Goodhart no valida automáticamente AB; una prueba de infraestructura, un hash o un commit tampoco valida una afirmación científica.

El [benchmark AB-E2E-01](benchmarks/AB_E2E_01/README.md) contiene un protocolo e instrumentación para comparar procedimientos. Su estado declarado es **preparado, sin ejecuciones científicas independientes de agentes**; las comprobaciones sintéticas de software se conservan por separado.

- Registrar cambios informativos mediante commits descriptivos, preservando versiones y motivos de revisión.
- Mantener privados estos materiales hasta una decisión humana de publicación; no incluir credenciales ni datos sin derechos de conservación.
- Enlazar informes extensos de Drive con repo, commit exacto, ciclos, fuentes y límites. Las discrepancias se resuelven mediante errata visible.
- Registrar las mejoras propuestas en el observatorio con fuente, alcance, contraevidencia y falsador; una incorporación documental no autoriza una actualización normativa silenciosa.
